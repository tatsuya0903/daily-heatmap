# Daily Heatmap

日別の件数データをカレンダー形式のヒートマップで可視化し、URLで手軽に共有できるWebアプリケーション。

現在はPhase 1の開発基盤、Issue #3のTSV読み込み・列選択・日付正規化、Issue #4のPC・スマートフォン向けヒートマップ表示、Issue #5の閾値5方式・8段階分類を実装しています。URL共有は後続Issueで実装します。仕様の管理元は [SPEC.md](./SPEC.md) です。

## TSV読み込み

トップ画面でUTF-8（BOMあり・なし）の`.tsv`／`.txt`を選択、またはドラッグ＆ドロップします。ファイルサイズは**2MiB（2,097,152バイト）以内**、最小日から最大日までの期間は**3,660日以内**です。制限値は`src/domain/limits.ts`にまとめています。

先頭列は`Date`、残りは重複しない空でない列名とし、タブで区切ります。LF・CRLFと末尾空行に対応します。以下は架空の入力例です。

```tsv
Date	Count
2026-04-01	6
2026-04-02	4
2026-04-11	45
```

複数列の場合は初期状態ですべて選択します。必要な1列以上を選択して「選択した列を読み込む」を押してください。次の例は全列選択時に上の例と同じ結果になります。

```tsv
Date	A件数	B件数
2026-04-01	3	3
2026-04-02	2	2
2026-04-11	21	24
```

日付は`0001-01-01`〜`9999-12-31`の実在する`YYYY-MM-DD`のみ、選択列の件数は0以上の10進整数のみです。空白・小数・負数・指数表記・カンマは受け付けません。各値と同日の合算値に`Number.MAX_SAFE_INTEGER`（9,007,199,254,740,991）の上限を適用します。

未選択列の値は数値として評価しませんが、全行の列数・日付・ヘッダーは検証します。重複日は加算せずエラーにします。エラー時は行番号・該当列・理由を表示し、列の選び直しやファイルの再選択ができます。全検証が完了するまではアプリの既存データを更新しません。

日付はUTC epoch dayで扱い、日付順に並べて未記録日を0件で補完します。末尾の0件も保持します。上の例はいずれも11日分の`[6, 4, 0, 0, 0, 0, 0, 0, 0, 0, 45]`になります。

Vueに依存しない`src/domain/`が解析（`parseTsv`）・選択列集計（`aggregateTsv`）・UTF-8読み込み（`readTsvFile`）・UTC日付変換を担当します。成功時は列名を含まない`ExactSeries`（`kind`・`startDate`・`counts`）をメモリー内のストアへ渡し、`/heatmap`で期間を確認できます。PC・スマートフォン共通のセルViewModelへ変換して描画します。

## ヒートマップ表示（Issue #4）

PC（幅960px以上）はVuetify 4.2.1 LabsのVHeatmapで、縦に日曜〜土曜、横に週を配置します。月見出しを表示し、長期間は領域内を横スクロールできます。幅960px未満は日曜始まりの月別7列カレンダーを縦に並べます。日付ボタンは高さ44px以上です。期間外のセルは作らず、未記録日と明示的な0件はいずれもグレーで表示します。

分類の初期値は**分位点（Quantile）**です。ヒートマップ上部で閾値を変更すると、元の件数を維持したまま、色・範囲・凡例・日付の詳細を即時更新します。現在選択している日付も維持します。

日付のホバー・タップ・フォーカスで、日付・正確な件数・レベル・件数範囲を詳細欄に表示します。タップ後も詳細は残り、スクロール中は上部に固定されます。Tabでカレンダーへ入り、矢印キーで日付を移動、Home／Endで期間の先頭／末尾へ移動、Enter／Spaceで選択できます。PCは上下で1日・左右で7日、スマートフォンは左右で1日・上下で7日移動します。Tabでカレンダーから抜けられます。

VHeatmap内部のSVGセルに`role="button"`、読み上げ用の日付・件数ラベル、フォーカス時の枠線を付けています。全3,660日をTabで巡回する必要がないよう、日付のTab停止位置は1か所にしています。月別表示も同じ操作とViewModelを使用します。凡例には全8色のレベルと件数範囲をテキストで表示します。

測定方法・環境・結果と残る確認事項は[Issue #4の検証記録](docs/issue-4-validation.md)を参照してください。性能テストは本番ビルド後、他テストと並行せず再現できます。

```sh
npm run build
npm run test:e2e -- e2e/heatmap-performance.spec.ts --workers=1
```

## 閾値設定（Issue #5）

- **固定プリセット**：ID 0「小規模」`2, 3, 5, 10, 20, 50`、ID 1「中規模」`50, 100, 300, 500, 700, 1000`、ID 2「大規模」`100, 500, 1000, 5000, 10000, 50000`。不変の定義から境界を導出します。
- **均等幅（Linear）**：正の最小〜最大を整数幅で分割します。BigIntで切り上げを計算し、最大安全整数付近の乗算・丸めの誤差を防ぎます。
- **分位点（Quantile・初期値）**：正の件数の昇順配列から、0始まりの`sorted[ceil(n*k/7)]`（`k=1..6`）を使用します。同じ件数を分割しません。
- **対数（Logarithmic）**：`log1p`で等分し、`expm1`で逆変換した候補を求めます。元の整数から導ける等価な7乗比較をBigIntで行い、必要に応じて二分探索して数学的な切り上げを確定します。値の大きさに比例する許容幅で小数を丸めることはしません。
- **カスタム**：6個の境界値を編集できます。2以上の安全整数を厳密な昇順で指定し、空欄・重複・小数・負数・指数表記・上限超過は日本語のエラーにします。不正な入力中は直前の正常な表示を維持します。

0件は常にレベル0、正の件数は最大7段階です。境界値は次のレベルの開始件数で、境界と一致する値は次のレベルへ入ります。自動3方式は0件を分布計算から除き、重複境界・範囲外候補を除去します。全0または正の件数がすべて同じ場合、自動方式の境界は空配列です。固定プリセット・カスタムの定義は維持します。凡例には全8色を示し、境界数が少ない場合は「未使用（範囲なし）」を明示します。

`src/domain/thresholds.ts`に検証・生成・分類・凡例を集約し、Vueに依存させていません。`ThresholdProfile`は確定境界を変更不可のコピーとして保持し、不整合なプリセットIDと境界値の組は拒否します。後続Codecは保存した境界を`normalizeThresholdProfile`で検証し、再生成せず使用できます。`ExactSeries`は正確な件数から分類を派生計算し、`LevelSeries`は保存済みレベルだけを表示して件数を推定しません。現行の設定用ストアは`ExactSeries`のみを受け付けます。Codec・URL生成・復元は今回の実装に含みません。

## データの取り扱い

TSVはブラウザー内で処理します。元のファイルをサーバーへ送信せず、ブラウザーの永続領域にも自動保存しません。個人データをリポジトリへ追加しないでください。ローカルの個人データ置き場として`private-data/`をGitの除外対象にしています。公開サンプルとテストには架空のデータのみを使用します。

共有機能はPhase 4で実装します。コンパクト形式は正確な件数を保持せず、完全データ形式は選択列の正確な日別合計を保持します。どちらのURLにも元の列名は含めません。URLは暗号化されません。
