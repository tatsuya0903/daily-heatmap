# Daily Heatmap

日別の件数をカレンダーで可視化し、自己完結したURLで共有するWebアプリです。TSVの読み込み、複数列の合算、未記録日の0補完、5方式の閾値設定、8段階の色分け、2種類のURL共有を実装しています。元ファイルはブラウザー内で処理し、サーバーへ送信しません。仕様の管理元は[SPEC.md](SPEC.md)です。

GitHub Pagesの公開フローは未整備です。このREADMEは稼働中の公開URLを案内していません。

## 使い方と合成サンプル

1. トップ画面でUTF-8の`.tsv` / `.txt`を選択するか、ドラッグ＆ドロップします。
2. 合算する件数列を1列以上選び、「選択した列を読み込む」を押します。最初は全列が選択されています。
3. 日付を選ぶと、日付・件数・レベル・範囲が詳細欄に表示されます。閾値方式を変更して分布を確認できます。
4. 「共有する」で形式を選び、URLをコピーします。新しいタブのアドレス欄に**URL全体**を貼り付け、Enterで開くと復元されます。

公開用の架空データは[public/sample.tsv](public/sample.tsv)です。実在の個人・LINE履歴・秘密情報は含みません。ローカルでは開発サーバーの`/daily-heatmap/sample.tsv`から保存するか、このファイルを読み込んでください。

```tsv
Date	A件数	B件数	C件数
2026-04-01	3	3	1
2026-04-02	2	2	0
2026-04-04	21	24	5
2026-04-05	0	0	0
```

全列なら5日分の`[7, 4, 0, 50, 0]`、C件数を外すと`[6, 4, 0, 45, 0]`になります。4月3日は入力にないため0件、4月5日は明示的な0件です。両者は区別せず表示し、末尾0を含む期間も維持します。

2列形式も使えます（列の区切りはタブ）。

```tsv
Date	Count
2026-04-01	6
2026-04-02	4
2026-04-04	45
2026-04-05	0
```

## 入力の制約

- UTF-8（BOMあり・なし）、LF / CRLF、末尾空行に対応します。ファイルは**2MiB（2,097,152バイト）以内**です。
- 先頭ヘッダーは`Date`。以降に空でない重複しない列名を付けます。日本語・空白入りの列名も使えます。
- 日付は`0001-01-01`〜`9999-12-31`の実在する`YYYY-MM-DD`のみです。重複日は合算せずエラーにします。
- 最小日〜最大日は**3,660日以内**。日付順に並べ、未記録日を0件で補完します。日付はUTC epoch dayで扱います。
- 選択列の件数は0以上の半角10進整数のみ。空欄、空白、負数、小数、指数表記、カンマは使えません。各値と選択列合計の上限は`Number.MAX_SAFE_INTEGER`（9,007,199,254,740,991）です。
- 未選択列の値は数値として評価しません。ヘッダー・日付・列数は全行で検証します。エラーでは行・列・理由を表示し、全検証に成功するまで既存データを更新しません。

## 閾値と表示

**0件は独立したレベル0（グレー）**、正の件数は最大7段階（グリーン）です。6個までの境界は「次のレベルが始まる件数」を表します。境界に一致すると次のレベルになります。全8色の凡例にレベルと件数範囲を示し、使わない段階には「未使用（範囲なし）」と表示します。

| 方式                       | 動作                                                                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 分位点（Quantile・初期値） | 正の件数を順位で区分。同じ件数は同じレベル                                                                                               |
| 固定プリセット             | ID0 小規模：2 / 3 / 5 / 10 / 20 / 50、ID1 中規模：50 / 100 / 300 / 500 / 700 / 1000、ID2 大規模：100 / 500 / 1000 / 5000 / 10000 / 50000 |
| 均等幅（Linear）           | 正の最小〜最大を均等な幅に区分                                                                                                           |
| 対数（Logarithmic）        | log1p / expm1と整数比較で、桁の違いを捉えやすい境界を確定                                                                                |
| カスタム                   | 2以上の安全整数6個を厳密な昇順で指定                                                                                                     |

自動3方式は0件を分布計算から除外し、重複・範囲外の境界を除去します。全0や正の値が同一の場合は境界なしです。カスタム入力が不正な間は直前の正常な表示を保ちます。URLでは確定した境界を保存し、復元時に勝手に再生成しません。公開済みプリセットIDの境界は変更しません。

PC（幅960px以上）は縦が曜日・横が週で、長期間はヒートマップ内を横スクロールします。幅960px未満は日曜始まりの月別7列カレンダーです。スマートフォンの日付セルは高さ44px以上です。

日付のホバー・タップ・フォーカスで詳細を表示します。Tab / Shift+Tabで操作箇所を移動し、日付には1か所のTab停止位置から入れます。矢印キーはPCで上下1日・左右7日、月別表示で左右1日・上下7日、Home / Endで期間の先頭 / 末尾、Enter / Spaceで選択します。macOS Safariではキーボードナビゲーションを有効にするかOption+Tabでボタン等へ移動します。共有ダイアログはTabの移動を内部に保ち、Escapeで閉じて共有ボタンへ戻ります。色に加えテキストと読み上げ用ラベルで日付・レベル・範囲を示します。

## 共有形式とプライバシー

| 表示元              | 正確な件数               | 閾値変更 | コンパクト再共有     | 完全データ再共有 |
| ------------------- | ------------------------ | -------- | -------------------- | ---------------- |
| TSV / 完全データURL | 表示できる               | 可       | 可                   | 可               |
| コンパクトURL       | 復元できない（範囲のみ） | 不可     | 同じレベル・境界で可 | 不可             |

共有の初期選択はコンパクトです。日付・3bitのレベル・確定閾値を保存します。正確な件数へ戻せない不可逆形式です。完全データ形式は選択列の**日別合計件数**を正確に保存し、復元後も閾値を変更できます。件数を必要とする相手には完全データを選んでください。

どちらもURLだけで復元でき、クラウド保存・認証・URL短縮サービスを必要としません。**元の列名・ファイル名・列別内訳・元TSV全文は含みません**。ただし、**URLは暗号化されません。URLを知る第三者は内容を解析できます**。コンパクトでも日付・レベル・件数範囲は解析できるため、秘密情報の保護手段として使わないでください。共有先アプリへ貼れば、そのアプリや受信者にもURLを渡すことになります。

URL全体の実文字数を共有前に表示し、**1,000文字超では警告**します。警告後もコピーできますが、アプリごとの長さ制限やリンク処理は保証しません。途中改行・省略・Hash欠落がないようURL全体を共有してください。デコード入力`d`の65,536文字上限は、この警告とは別です。

Clipboard APIの非対応や拒否では手動コピーを案内し、URL欄にフォーカスして全文を選択します。端末のコピー操作を使い、新しいタブのアドレス欄へ貼り付けて開いてください。共有前に新しいタブでの復元を確認すると確実です。

ブラウザーの永続領域へデータを自動保存しません。TSVから表示した`d`なしの画面を再読み込みするとデータを失うため、必要なら共有URLを保存してください。不正URLでは部分的なデータや以前のストア内容を表示せず、エラーと復帰先を示します。私的ファイルはGit除外対象の`private-data/`へ置き、コミットしないでください。

## 開発と品質検査

Node.js **24.21.0**、npm **11.19.0**で検証しています。Nodeは`engines` / Volta、依存は`package-lock.json`で固定します。

```sh
npm ci
npm run dev
```

開発サーバーの`/daily-heatmap/`を開きます。本番ビルドのプレビューは`npm run preview`です。

```sh
npm run type-check
npm run lint
npm run format:check
npm run test:unit
npx playwright install
npm run build
npm run test:e2e -- --workers=1
git diff --check
```

`lint`と`format:check`は書き換えません。修正は`npm run lint:fix`、整形は`npm run format`です。`npm run test`で単体・E2Eを順に実行できます。E2Eは事前ビルドが必要で、本番previewを自動起動します。5構成はChromium / Firefox / WebKit / mobile-chrome / mobile-safari。後者2つは端末エミュレーションです。通常workerの検証は`npm run test:e2e`で実行します。

単体ではTSV・日付・閾値・Codec・ストア・コンポーネント、E2Eでは入力から共有・直接URL復元、モード制限、履歴、不正入力、キーボード操作を確認します。DST等の日付単体は`TZ=UTC`、`TZ=Asia/Tokyo`、`TZ=America/New_York`を付けて再実行できます。受け入れ条件の対応、監査と性能の詳細は[Issue #9検証記録](docs/issue-9-validation.md)を参照してください。

## Hash Routerと公開手順

Viteの`base`は`/daily-heatmap/`です。Hash Routerのルートは`#/heatmap?d=...`。`d`を通常のURLクエリではなくHash内に置くため、静的ホストは`/daily-heatmap/`の入口を配信するだけで、共有ページを直接開けます。Hash内のデータはHTTPのページ要求には含まれません。

**現在、CI / Pagesデプロイ用の`.github/workflows/`はありません**。ローカル検査とIssue #10で予定する自動化を区別してください。Issue #10では品質検査とE2EのCI、承認済みリリースタグからのPages公開を整備する予定です。mainの更新だけで自動公開する設計ではありません。

公開担当者の手順：まずIssue #10で実在するworkflowとPages設定を整備・レビューし、全品質検査とビルドを確認します。その後、push・PR・マージ・タグ・公開についてそれぞれ明示承認を得ます。承認された公開フローが成功して初めて、実際に表示されたURLを確認・案内し、以下の実機受け入れを実施してください。現時点で実行できる公開コマンドや稼働中URLは記載しません。

開発は最新mainからIssue専用の`codex/<Issue番号>-<内容>`ブランチで行い、mainへ直接変更・コミットしません。原則1 Issue / 1 PR、Squash and mergeです。push・PR作成・マージ・タグ・公開デプロイは各々ユーザーの明示承認後に行います。

## 公開後のLINE・実機手動受け入れ

**未実施**です。PlaywrightのスマートフォンエミュレーションはLINEや実機OSの検証を代替しません。iPhone / Androidそれぞれで、端末名・OS・ブラウザー・LINEのバージョン、実施日、実際の公開URL、合否を記録してください。合成サンプルだけを使います。

1. 公開ページでサンプルを読み込み、C件数を外して`[6, 4, 0, 45, 0]`を確認します。閾値をカスタム等へ変更し、期間・確定境界・凡例・各日付の色/レベルを記録します。
2. コンパクトURLをコピーし、端末の新しいブラウザータブへ直接貼って開きます。Clipboard拒否時はURL欄から手動コピーを試します。
3. LINEの自分用テスト送信先へURL全体を貼り付け、送信します。受信リンクをLINE内ブラウザーで開き、さらに外部ブラウザーでも開きます。
4. コピーした元URLと開いたページのアドレスを比べ、`#/heatmap?d=`の**Hash内のd全体**が欠落・切断・変換されていないか確認します。画面の期間・日付・レベル・色・凡例・境界が元と一致することを確認します。
5. コンパクトでは正確な件数が表示/読み上げされず範囲のみ、閾値変更と完全共有が無効、コンパクト再共有では同じ内容になることを確認します。
6. 元のTSV表示へ戻り、完全データURLで同じコピー・送信・開く操作を繰り返します。5日分の正確な合計と末尾0、境界が一致し、閾値変更後に両形式で再共有できることを確認します。
7. 1,000文字超の合成URLも試し、警告・全文コピー・Hash保持を確認します。失敗時はアプリ/バージョン・文字数・切断箇所を記録し、成功したとは扱いません。
8. VoiceOver / TalkBackでラベル・エラー/コピー通知・ダイアログ移動と復帰を確認します。PCのNVDA等とブラウザーの200% / 400%拡大、OSのハイコントラストも別途記録します。ネイティブselectのpopupをキーだけで開いて5方式を変更し、画面高さが低いときもフォーカスが隠れないことを確認します。

## 既知の制限と未検証項目

- URL短縮、クラウド保存、認証、元の列別内訳の復元はありません。共有URLの長さ・LINE等でのリンク保持は端末やアプリ版に依存します。
- 公開後のLINE共有、iPhone / Android実機、スクリーンリーダー実機、ブラウザー自体の200% / 400%拡大、ネイティブselectのpopupの実機キー操作、低速端末は未検証です。640px / 320pxの自動リフロー検査とは区別します。
- WCAG 2.2 AAを参考に監査していますが、完全準拠を宣言するものではありません。色の違いだけに依存せず詳細・凡例・ARIA説明で補います。
- 最大3,660日は全セルを描画します。ブラウザーによる再描画性能の差と残る負荷は検証記録を参照してください。
- Vuetify VHeatmapはLabsです。依存更新時は描画・フォーカス・色・性能とCodecの互換性を確認してください。
